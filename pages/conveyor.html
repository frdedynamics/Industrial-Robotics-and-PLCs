Conveyor System

Project role

In this part of the project, you will build and test the conveyor system that supplies workpieces to the robot cell. Visual Components (VC) represents the physical plant: it creates products, transports them, and routes them at a series of pusher conveyors. The completed conveyor model is later connected to the robot-cell project.

This page guides you through the work in the intended order. First make the complete conveyor system work using VC’s internal component behavior. Do not begin with PLC communication. A working internal model gives you a known plant before an external controller and communication delays are introduced.

The required version uses the standard Pusher Conveyor’s internal routing logic. When the conveyor is integrated with the robot cell, the PLC will command the ordinary conveyors without replacing this routing. PLC control of the complete push cycle is a separate possible extension.

By completing this stage, you should be able to:

  • create product types and generate a defined product mixture,
  • assemble connected conveyor components,
  • use component properties, behaviors, interfaces, and signals,
  • configure and test product routing, and
  • prepare a tested conveyor sublayout for integration with the robot cell.

Required behavior

The conveyor system shall repeatedly perform the following material flow:

  1. The Advanced Feeder creates blue, red, green, purple, and grey cylinders.
  2. A shared run signal starts and stops the ordinary conveyor paths.
  3. Four Pusher Conveyors sort the blue, red, green, and purple cylinders onto separate side conveyors.
  4. Grey cylinders pass all four pushers and continue toward the robot cell.

Figure 1 summarizes both the product routes and the shared run command. Product routing and control of each pusher’s local path remain inside the Pusher Conveyors in the required version.

For this first model, each side conveyor represents downstream storage with unlimited capacity. You do not need to model storage limits or congestion after a product has left its sorting station.

The conveyor system does not use the VC Conveyor Motor component. Conveyor motion is controlled through the conveyors’ path signals, and conveyor fault handling is not part of this stage.

Build and test in Visual Components

Organize the conveyor sublayout

Start with an empty VC layout. In the Layouts tab of the Cell Graph, create a sublayout named Conveyor system. You can place components in the 3D world first and then use Move to Layout to assign them to this sublayout.

Create the product types

The product types define the identity and geometry of the items generated by the feeder. A product’s colour alone does not define a product type.

Create the five types as follows:

  1. Add a Cylinder from Basic Shapes to the layout.
  2. Set its material to the first required colour.
  3. Open Process > Product Type Editor and select the plus button.
  4. Name the new product type according to Table 1.
  5. In ComponentUri, use Pick Component and select the corresponding coloured cylinder.
  6. Repeat the process for the other four colours.

Keep the five template cylinders away from the transport path. After configuring the feeder, verify that the generated instances have the expected product type and appearance.

Configure the Advanced Feeder

Add an Advanced Feeder to the layout. Its position and connection are handled when you build the first sorting station. In the feeder’s component properties:

  1. Set CreationMode to Distribution.
  2. Open the DistributionBook tab.
  3. Select Open in Editor.
  4. Keep the first two column headings exactly as ProductType and Probability.
  5. Copy the following CSV data into the editor:
ProductType,Probability
Cylinder_blue,23.75
Cylinder_red,23.75
Cylinder_green,23.75
Cylinder_purple,23.75
Cylinder_grey,5.00

The distribution is useful for repeated mixed-flow testing. While testing one route, you may temporarily increase the probability of the relevant product type instead of waiting for it to occur randomly. Restore the intended distribution before validating the complete system.

Build and configure one sorting station

Place an incoming Conveyor, one Pusher Conveyor, and one side Conveyor. Position the configured feeder at the beginning of the incoming Conveyor, then connect all compatible interfaces and check that the path directions are consistent. Leave enough straight path before the pusher for products to enter its detection region reliably.

Configure the physical properties that should be common to every station, such as conveyor dimensions, height, and speed. On the Pusher Conveyor, set RouteBy to RoutingRule, open the RoutingRule editor, select Product Type Rule, and set the default connection to Out. Do not assign a product type yet.

Run the simulation and confirm that products pass through the station without jumping, rotating unexpectedly, or becoming stuck at an interface. Correct the common settings before creating copies.

Duplicate and connect the sorting stations

Select the configured Pusher Conveyor together with its side Conveyor and duplicate the pair three times. Connect the straight Out interface of each Pusher Conveyor to the input of the next one, forming a line of four sorting stations. Add an ordinary conveyor after the final Out connection for the grey cylinders.

Because the shared physical settings and the Product Type Rule were configured before duplication, only the station-specific routing now needs to be changed. Adjust spacing or conveyor lengths where needed, then run products through the complete line once with all four rules still using their default Out route.

Configure run control for the ordinary conveyors

Use one of the ordinary conveyors’ existing Boolean PowerOnSignal values as the shared run command:

  1. Select an ordinary conveyor and show its component signals.
  2. Draw signal connections from its PowerOnSignal to the PowerOnSignal of each remaining ordinary conveyor.
  3. Use the selected conveyor’s signal as the single run command for the line.

Change the shared value manually and verify that all connected paths start and stop together. Test this again after resetting the simulation. Some component behaviors react when a signal value changes, so explicitly toggle the command once rather than assuming that its initial value has already been applied.

Do not connect this signal to the Pusher Conveyor’s One-WayPath. Its internal script temporarily stops and restarts that path while transferring a product. Connecting another signal to the same Enabled property would create two independent writers whose commands can overwrite one another.

The shared signal provides one clear line-level command for the ordinary conveyors. It can later be mapped to the PLC without mapping those conveyors separately.

Configure internal pusher routing

The standard Pusher Conveyor contains internal logic that detects, attaches, moves, and transfers a product to the selected outgoing path. Use that complete behavior at each station:

  1. At pusher 1, assign Cylinder_blue to Pusher.
  2. At pusher 2, assign Cylinder_red to Pusher.
  3. At pusher 3, assign Cylinder_green to Pusher.
  4. At pusher 4, assign Cylinder_purple to Pusher.
  5. Keep Out as the default connection in every rule so that all other product types continue to the next station.

Do not replace this behavior by controlling only the visible pusher joint. The joint motion alone does not perform the product attachment and transfer between conveyor paths.

Run the system until every product type has passed through the sorting line. Confirm that each coloured type leaves at its assigned side conveyor and that grey cylinders pass all four pushers and continue through the final outlet.

Validate the internal model

Test the conveyor system incrementally and then run a longer mixed sequence. Verify that:

  • the feeder creates all five product types with the intended appearance,
  • the shared run signal starts and stops every ordinary conveyor path,
  • products cross each conveyor interface reliably,
  • every pusher completes its full extension, transfer, and retraction sequence,
  • each coloured product enters its assigned side path,
  • grey products continue through the straight path, and
  • resetting and restarting the simulation produces repeatable behavior.

Save this working version before adding the robot cell or external communication. It becomes the known-working conveyor plant used in the next project stage.

Checkpoint before robot-cell integration

Before continuing to the robot cell, you should be able to demonstrate:

  • the configured product types and feeder distribution,
  • the complete conveyor layout in the Conveyor system sublayout,
  • common start and stop behavior for the ordinary conveyors,
  • correct internal routing at all four sorting stations, and
  • repeatable operation after a simulation reset.

Save a checkpoint copy of the layout and document the important component settings and tests. Use this copy to return to the independently working conveyor if a later integration change causes a problem.

Connect the robot cell

Build the robot cell in the same VC file but initially leave space between the two sublayouts. The robot-cell instructions explain how to create the Robot cell sublayout and develop it with a copied feeder that produces only grey cylinders. This avoids waiting for a rare grey part while robot poses and motions are being tested. Keep the original feeder and its mixed distribution unchanged; modify only the temporary copy in the robot-cell sublayout.

After the robot-cell program works independently, follow Integrate the conveyor and robot-cell sublayouts to remove the temporary feeder and connect the straight conveyor outlet to the robot pickup conveyor. Start the original mixed feeder again and confirm that the sorting stage removes the coloured products while grey cylinders reach the robot.

External control boundary

The internally controlled pusher is the required and testable starting point. The distinction between internal VC control and external PLC control is explained on the VC page, while the PLC-integration section explains the wider purpose of connecting CODESYS and the simulation.

In the robot cell’s external-control stage, map the shared PowerOnSignal to CODESYS so that the PLC starts and stops the ordinary conveyors. Product routing and the pusher’s local path control remain internal to VC. This adds PLC line control without introducing another pusher state machine.

Possible extension: PLC-controlled pushing

Full PLC control of the push cycle requires a tested interface that requests one complete transfer and receives completion feedback. Directly commanding the pusher joint is not sufficient.

Full PLC control of the push cycle is not part of the required stage. Treat it as an extension only after the required conveyor and robot-cell coordination works reliably.

Optional signal investigations

The internally routed model does not require an external colour signal. The following investigations are relevant only if you want to inspect the component in more detail or if a later PLC extension is assigned.

To expose the Pusher Conveyor’s built-in product detector as a Boolean signal:

  1. Add a BooleanSignal behavior named PartDetected.
  2. Open the ComponentPathSensor behavior.
  3. Set its BoolSignal property to PartDetected.
  4. Run products through the pusher and verify the signal transition.

You can also investigate the Conveyor Sensor component’s RGB detection:

  1. Add the sensor to an ordinary conveyor and reset the simulation.
  2. Open the sensor’s RGB properties and enable colour detection.
  3. Place one of the coloured template cylinders inside the detection area.
  4. Select Teach in color 1.
  5. Repeat for the remaining colours and observe the resulting outputs.

The RGB sensor reads the simulated material in its detection area, not the product-type name. Therefore, verify its outputs with products generated by the feeder before using them in control logic. RGB detection does not replace the product-type routing used in the required model.
